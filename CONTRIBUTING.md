# Contributing

Thank you for helping make this collection more useful.

## Before opening a pull request

1. Search `ideas/index.json` and GitHub for the central concept.
2. Read the existing solutions and write down the meaningful gap.
3. Use primary sources where possible: official documentation, public datasets, published research, issue trackers, or government material.
4. Create one Markdown file from [the idea template](ideas/TEMPLATE.md).
5. Add the item to `ideas/index.json` and run `node tools/validate-ideas.mjs`.

## Evidence standard

Keep claims specific and attributable. Link a source for the problem and at least one existing solution. Summarize in your own words. Do not copy descriptions from another project, paper, or website.

## Duplicate policy

An entry is not original just because it has a new name. If an equivalent project exists, do one of the following:

- do not submit it;
- document the existing project and a testable gap; or
- contribute to the existing project instead.

The gap must change the user, workflow, constraint, or outcome in a material way.

## Style

Use direct, plain sentences. Avoid hype, vague promises, emojis, and decorative wording. Do not use text generated by a language model as evidence or as a substitute for research.

## Review

Maintainers verify the sources, duplicate search, scope, and template before merging. A rejected idea can be revised with stronger evidence.
